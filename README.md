# CS-305-Software-Security
Software Security portfolio featuring the Artemis Financial Vulnerability Assessment and Practices for Secure Software projects, demonstrating vulnerability analysis, secure coding, cryptography, and software security testing.

### 1. Client and Software Requirements

Artemis Financial is a financial consulting company that provides individualized financial services to its clients, including savings, retirement, investments, and insurance. The company wanted to improve the security of its existing software application to better protect sensitive financial information and establish a more secure method of communication. My responsibility was to assess the application's security vulnerabilities and identify the necessary improvements that would strengthen its overall security infrastructure. This included evaluating potential risks, implementing secure coding practices, and incorporating cryptographic techniques to maintain data integrity and confidentiality.

### 2. Software Security Assessment

One of the areas I believe I performed well in was identifying potential security vulnerabilities within Artemis Financial's software application and evaluating how those vulnerabilities could compromise the system's overall integrity. Throughout the assessment, I focused on examining the application's dependencies, identifying potential security risks, and determining which areas required additional mitigation. I also gained a better understanding of how important it is to implement secure coding practices throughout the software development lifecycle rather than addressing vulnerabilities after development. Secure coding is essential because even a minor vulnerability could potentially compromise sensitive financial information or create additional attack vectors. For a company like Artemis Financial, maintaining strong software security not only protects client information but also reinforces customer confidence, preserves business continuity, and reduces the likelihood of financial and reputational damage.

### 3. Challenges and Lessons Learned

One of the more challenging aspects of the vulnerability assessment was determining which identified vulnerabilities presented an actual security risk and which required additional investigation. Using OWASP Dependency-Check helped me better understand how software dependencies can introduce vulnerabilities into an application, even when the source code itself appears secure. Another challenge was distinguishing between legitimate security concerns and potential false positives, which required additional analysis before determining the appropriate mitigation strategy. Overall, this process was beneficial because it reinforced the importance of conducting a thorough assessment, validating the results, and prioritizing vulnerabilities based on their potential impact rather than making assumptions based solely on the initial scan.

### 4. Security Improvements and Mitigation Techniques

Throughout this project, I increased the application's layers of security by implementing cryptographic techniques, including SHA-256 checksum verification, HTTPS communication, and a self-signed digital certificate to strengthen data integrity and secure communication. These improvements helped establish additional safeguards against unauthorized access, data manipulation, and potential security vulnerabilities. I also utilized OWASP Dependency-Check to identify vulnerable dependencies and evaluate potential risks within the application's existing framework. In future projects, I would continue utilizing vulnerability scanning tools, CVE databases, and established security standards to assess potential threats and determine the most appropriate mitigation strategies. I believe that implementing multiple layers of protection, while continuously evaluating their effectiveness, provides a more comprehensive and sustainable approach to maintaining software security.

### 5. Functional Testing and Vulnerability Verification

To ensure that the software application remained functional and secure, I conducted additional testing after implementing the security improvements to verify that the application continued operating as intended. This included examining the HTTPS connection, validating the SHA-256 checksum functionality, and reviewing the application's behavior after incorporating the digital certificate. I also utilized OWASP Dependency-Check to identify potential vulnerabilities within the application's dependencies and determine whether additional mitigation was necessary. After refactoring the code, I focused on verifying that the security improvements did not introduce new vulnerabilities or compromise the application's existing functionality. This process reinforced the importance of continuous testing, code validation, and maintaining a balance between application functionality and security throughout the software development lifecycle.

### 6. Tools, Resources, and Coding Practices

Throughout both projects, I utilized several tools and resources that strengthened my understanding of software security and provided practical experience that I can apply to future assignments. OWASP Dependency-Check was particularly beneficial because it allowed me to identify potential vulnerabilities within third-party dependencies and evaluate their associated CVE records. I also utilized Java keytool to generate a self-signed digital certificate and incorporated SHA-256 checksum verification to validate data integrity. Additionally, Oracle's Java security documentation, the CVE Program, and OWASP resources provided valuable guidance when researching cryptographic algorithms, vulnerability classifications, and mitigation techniques. Moving forward, I intend to continue incorporating secure coding practices, dependency analysis, and continuous security testing throughout the software development lifecycle. These resources and techniques will be instrumental in developing applications that are not only functional but also resilient against emerging security threats.

### 7. Professional Portfolio and Future Applications

I would utilize both Artemis Financial projects to demonstrate my ability to identify software vulnerabilities, implement security improvements, and evaluate the effectiveness of secure coding practices. Project One demonstrates my ability to conduct a vulnerability assessment, analyze potential security risks, and recommend appropriate mitigation strategies. Project Two expands upon those skills by demonstrating the practical implementation of cryptographic techniques, secure communication protocols, and dependency vulnerability scanning. Together, these projects showcase my understanding of how software security must be incorporated throughout the development lifecycle rather than treated as a secondary consideration. For future employers, particularly within government contracting, cybersecurity, and software engineering, I believe these projects provide tangible evidence of my technical proficiency, analytical reasoning, and ability to approach security concerns methodically.
